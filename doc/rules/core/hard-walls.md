# 🚨 절대 금기 사항 및 보안 수칙 (v0.6.0)

## 1. 보안 지침 (Security Mandates)

- **IDOR 방어**: 모든 API 호출 및 리소스 조회 시 사용자 세션 아이디와 리소스 소유권을 대조하는 로직을 필수로 구현합니다.
- **RLS 철칙**: 데이터베이스 레벨에서 `USING (true)`와 같은 개방형 정책을 절대 작성하지 않으며, 최소 권한 원칙을 준수합니다.
- **Secrets Management**: API 키 및 보안 자격 증명은 절대로 코드에 하드코딩하지 않으며, 반드시 `.env` 및 Vercel 환경 변수를 통해 관리합니다.
- **Input Validation**: 클라이언트에서 넘어오는 모든 데이터는 Zod 스키마를 통해 살균 및 검증 과정을 거칩니다.

## 2. 3-Strike 정책 (Anti-Loop)

- 동일한 에러가 2회 발생하면 기존 접근 방식을 즉시 폐기하고 완전히 새로운 전략을 수립합니다.
- 3회 연속 실패 시 자의적인 수정을 중단하고, 실패한 3가지 접근법과 유력 원인을 정리하여 사용자에게 보고하고 지침을 대기합니다.

## 3. 리소스 보호 (Integrity)

- 사용자의 명시적 요청 없이 기존의 주석, 안정적인 로직, 또는 유효한 코드를 대량으로 삭제하거나 변경하지 않습니다.
- 모든 리팩토링은 기능적 동등성이 보장된 상태에서 진행합니다.
