# [최종 리뷰 패키지] 유저 권한별 UI/UX 분기 및 관리자 메뉴 구현 보고

## 1. 개요
본 문서는 CEO 요청 사항인 "관리자 권한 유저의 전용 메뉴 미노출" 문제를 해결하기 위한 기술적 분석 결과와 실제 구현 내용을 정리합니다. 유저 권한(Role)에 따른 네비게이션 분기 처리를 통해 관리자 전용 기능을 안전하고 직관적으로 제공합니다.

## 2. 현황 및 문제점 분석
- **기술적 원인**: 세션(NextAuth)에서는 유저의 role 정보를 정상적으로 보유하고 있었으나, 프론트엔드 핵심 컴포넌트인 Header.tsx와 MobileMenu.tsx에서 이를 참조하여 UI를 분기하는 로직이 누락됨.
- **영향**: 관리자(admin) 권한을 가진 유저도 일반 유저와 동일한 메뉴만 보게 되어 관리자 페이지(사용자 관리, 구독 관리 등)로의 접근 경로가 차단됨.

## 3. 어드민 전용 메뉴 요구사항 (Specification)
개발팀 아리아 팀장님의 보완 요청을 반영하여 다음과 같은 어드민 전용 메뉴를 확정하고 구현하였습니다.

| 메뉴명 | 연결 경로 (Href) | 비고 |
| :--- | :--- | :--- |
| **사용자 관리** | /admin/users | 전체 유저 목록 조회 및 권한 수정 |
| **구독 관리** | /admin/subscription | 플랜별 구독 현황 및 결제 데이터 모니터링 |
| **콘텐츠 관리** | /admin/posts | 플랫폼 내 생성된 전체 포스트 관리 (예정) |

## 4. 구현 상세 (Implementation)

### 4.1. 다국어 지원 (i18n)
- messages/ko.json, messages/en.json에 어드민 전용 라벨 추가.
- adminUsers, adminSubs 등 신규 번역 키 정의.

### 4.2. UI 컴포넌트 수정
- **Header (Desktop)**: session.user.role === 'admin' 조건문을 통해 설정 메뉴 우측에 어드민 메뉴 그룹을 노출. 시각적 구분을 위해 세퍼레이터(Separator) 적용.
- **MobileMenu (Mobile)**: role 프로퍼티를 신규 추가하여 드롭다운 내부에 "Admin" 섹션을 별도로 분리하여 노출.

### 4.3. 권한 보장 로직 (auth.ts)
- 기존 기획팀 클리오의 제안대로 DB 조회 실패 시 기본값("user")을 부여하는 방어적 로직을 유지하여 시스템 안정성 확보.

## 5. QA 검토 및 테스트 전략 (Lint, Senior QA)
품질관리팀은 본 구현 사항에 대해 다음의 품질 검증 기준을 수립하고 테스트를 수행할 계획입니다.

### 5.1. 핵심 테스트 시나리오 (E2E)
| 시나리오 ID | 테스트 목적 | 기대 결과 (Expected Result) |
| :--- | :--- | :--- |
| **TC-NAV-01** | 일반 유저(user) 메뉴 노출 검증 | 어드민 전용 메뉴(사용자 관리, 구독 관리)가 절대 노출되지 않아야 함. |
| **TC-NAV-02** | 어드민 유저(admin) 메뉴 노출 검증 | Header 및 MobileMenu에 어드민 전용 섹션이 정상 노출되어야 함. |
| **TC-NAV-03** | **DB 장애 상황 폴백 검증** | upsertProfile 실패 시 admin 유저도 user로 안전하게 강등되며, 시스템이 크래시되지 않아야 함. |
| **TC-NAV-04** | 반응형 어드민 메뉴 검증 | 모바일(MobileMenu) 환경에서 어드민 메뉴가 레이아웃을 해치지 않고 정상 렌더링되어야 함. |

### 5.2. 리스크 분석 및 대응 (Risk Mitigation)
- **DB 장애 시 권한 강등 리스크**: auth.ts의 폴백 로직에 의해 어드민 유저가 일시적으로 user 권한으로 인식될 수 있습니다. 이는 보안상으로는 안전(deny-by-default)하지만, 운영 측면에서는 관리 기능이 일시 중단되는 가용성 이슈가 발생할 수 있습니다.
- **대응 방안**: DB 연결 상태를 실시간 모니터링하고, auth.ts에서 발생하는 Failed to sync profile 에러에 대한 로깅을 강화하여 즉각 대응 가능한 체계를 구축합니다.

## 6. 기대 효과
- **운영 효율성**: 관리자가 별도의 주소 입력 없이 UI를 통해 즉시 관리 페이지로 진입 가능.
- **보안 및 UX**: 일반 유저에게는 관리자 메뉴를 노출하지 않으면서, 관리자에게는 명확한 시각적 위계(Admin 라벨 등)를 제공.
- **품질 보증**: 권한별 엄격한 분리 및 예외 상황 대응 로직을 통해 서비스 안정성을 확보함.

## 7. 결론 및 잔여 리스크
CEO 요청 사항에 따른 문제 파악 및 UI 반영이 완료되었습니다.

**[잔여 리스크]**
1. **E2E 테스트 자동화 미흡**: 현재 수동 검증 위주로 진행되었으므로, 향후 Playwright 등을 이용한 권한별 접근 제어 자동화 테스트 커버리지 확보가 필수적입니다.
2. **시각적 위계 조정**: 디자인팀 의견에 따라 어드민 전용 메뉴의 색상이나 아이콘 등에 대한 추가적인 스타일링 조정이 발생할 수 있습니다.
3. **서버 사이드 가드 강화**: UI 분기 외에도 admin/* 경로에 대한 서버 사이드 미들웨어 권한 가드 로직을 추가하여 보안 완결성을 높여야 합니다.
