# Feature Specification: Marketing Demo Page

**Feature Branch**: `001-marketing-demo`  
**Created**: 2026-03-25  
**Status**: Draft  
**Input**: User description: "유저들에게 마케팅 용도로 사용할 데모버전 페이지가 필요해. 기존의 demo 페이지는 이름을 변경해서 archive해주고, 새로운 demo로 route 사용해줘. 해당 페이지에는 현재 작성되어 있는 모든 글을 볼 수 있어야 해. 로그인한 유저들이 메인페이지에서 볼 수 있는 내용과 똑같을 거야. 대신 글의 내용만 볼 수 있어야 하고, 수정 삭제 기능들은 모두 삭제되어야 해. 글의 본문에서도 작성자에 대한 소개 및 레포지토리, 아이디 정보는 표시되지 않도록 하고, 커밋 메세지 클릭 시 github 링크 이동 기능도 삭제해줘. 제목 상단에 ~~의 블로그로 돌아가기 기능도 삭제하고 이전페이지로 이동 기능만 추가해줘. 메뉴바에는 모든 메뉴를 삭제하고 우측에 "테스터 신청" 메뉴, 언어변경메뉴와 좌측 로고만 보이도록 해줘."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Public Demo Viewing (Priority: P1)

잠재 고객(방문자)으로서 서비스에 가입하거나 로그인하지 않고도 서비스가 생성하는 기술 블로그의 품질을 확인할 수 있도록 실제 생성된 포스트들을 둘러보고 싶다.

**Why this priority**: 마케팅의 핵심 도구로서 서비스의 가치(포스트 품질)를 직접 보여주는 것이 가장 중요하다.

**Independent Test**: 비로그인 상태로 `/demo` 경로에 접속하여 포스트 목록이 정상적으로 표시되고, 개별 포스트를 읽을 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 익명의 방문자가 `/demo`에 접속했을 때, **When** 페이지가 로드되면, **Then** 시스템에 등록된 모든 공개 포스트가 목록으로 표시된다.
2. **Given** 데모 포스트 목록에서 특정 포스트를 클릭했을 때, **When** 상세 페이지로 이동하면, **Then** 포스트의 본문 내용이 정상적으로 표시된다.

---

### User Story 2 - Restricted Interactions (Priority: P2)

데모 페이지를 이용하는 동안 실수로 데이터를 수정하거나 외부(GitHub 등)로 유출되는 것을 방지하고, 데모 목적에 맞게 읽기 전용 경험만 유지하고 싶다.

**Why this priority**: 데이터 무결성 보호 및 마케팅 집중도를 높이기 위해 불필요한 기능(수정/삭제/외부링크)을 제거해야 한다.

**Independent Test**: 데모 상세 페이지에서 수정/삭제 버튼이 없고, 커밋 메시지 클릭 시 GitHub로 이동하지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 데모 포스트 상세 페이지에서, **When** 화면을 확인하면, **Then** 수정 및 삭제 버튼이 보이지 않아야 한다.
2. **Given** 포스트 본문 내 커밋 메시지를 클릭했을 때, **When** 동작을 확인하면, **Then** 외부 GitHub 리포지토리로 이동하지 않아야 한다.
3. **Given** 포스트 상세 페이지 상단에서, **When** 내비게이션을 확인하면, **Then** "~~의 블로그로 돌아가기" 대신 "이전 페이지로 이동" 버튼만 존재해야 한다.

---

### User Story 3 - Specialized Demo Header (Priority: P3)

데모 페이지의 헤더를 단순화하여 방문자가 다른 복잡한 메뉴에 방해받지 않고 서비스의 핵심 기능(데모 확인 및 테스터 신청)에만 집중하게 하고 싶다.

**Why this priority**: 데모 환경에서의 사용자 경험을 최적화하고 전환(테스터 신청)을 유도하기 위함이다.

**Independent Test**: `/demo` 페이지의 헤더에 로고, 테스터 신청, 언어 변경 메뉴만 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 데모 페이지의 헤더에서, **When** 좌측 구역을 확인하면, **Then** 로고만 표시된다.
2. **Given** 데모 페이지의 헤더에서, **When** 우측 구역을 확인하면, **Then** "테스터 신청" 링크와 "언어 변경" 드롭다운만 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기존의 `/demo` 경로를 사용하는 페이지를 다른 경로(예: `/demo-archive`)로 이전하거나 이름을 변경하여 보관해야 한다.
- **FR-002**: 시스템은 새로운 마케팅용 데모 페이지를 `/demo` 경로에서 제공해야 한다.
- **FR-003**: 데모 페이지는 로그인 여부와 관계없이 모든 사용자가 접근 가능해야 한다.
- **FR-004**: 데모 페이지는 시스템에 저장된 모든 "공개(Published)" 상태의 포스트를 최신순으로 표시해야 한다.
- **FR-005**: 포스트 상세 페이지에서는 작성자 이름, 프로필 소개, GitHub 아이디, 리포지토리 정보 등 개인 식별 정보를 숨겨야 한다.
- **FR-006**: 포스트 본문의 커밋 메시지는 텍스트로만 표시되거나 클릭 시 아무 동작도 하지 않아야 한다 (GitHub 외부 링크 제거).
- **FR-007**: 포스트 상세 페이지 상단 내비게이션은 브라우저의 '뒤로 가기'와 동일한 기능을 수행하는 "이전 페이지로 이동" 링크를 제공해야 한다.
- **FR-008**: 데모 전용 레이아웃/헤더를 적용하여 홈, 프로필, 설정 등의 일반 메뉴를 제거해야 한다.

### Key Entities

- **Post**: 데모 페이지에서 보여줄 핵심 데이터. 제목, 본문, 생성일 등의 속성을 가짐.
- **TesterApplication**: 데모 페이지 헤더의 "테스터 신청" 메뉴를 통해 연결될 신청 정보.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 익명의 사용자가 추가 인증 없이 `/demo` 페이지 로드에 성공해야 한다.
- **SC-002**: 데모 포스트 상세 페이지 내에 "GitHub.com"으로 향하는 외부 링크가 하나도 존재하지 않아야 한다.
- **SC-003**: 데모 페이지 내에서 개인 식별 정보(PII)가 포함된 DOM 요소가 0개여야 한다.
- **SC-004**: 사용자가 데모 페이지에서 "테스터 신청"을 클릭했을 때 신청 폼으로 100% 이동 성공해야 한다.

## Assumptions

- **A-001**: "현재 작성되어 있는 모든 글"은 데이터베이스상에서 공개 가능한 상태로 마킹된 글들을 의미한다.
- **A-002**: 기존 demo 페이지는 `/demo/archive` 또는 유사한 비공개 경로로 이동된다.
- **A-003**: "이전 페이지로 이동" 기능은 브라우저 히스토리를 사용하거나 데모 목록 페이지로 리다이렉트하는 방식으로 구현된다.
- **A-004**: 다국어 지원(i18n)이 이미 프로젝트에 구축되어 있으며, 데모 페이지 헤더에서도 기존 언어 변경 컴포넌트를 재사용한다.
